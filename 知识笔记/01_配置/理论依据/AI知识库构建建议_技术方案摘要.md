## 一、文件组织结构

### 1.1 推荐的Obsidian仓库结构

```
MyKnowledge/
├── 00_DataSources/        # 第一层：原始数据（书籍MD、视频字幕）
├── 01_Summaries/          # 第二层：摘要（与数据源一一对应）
├── 02_Cards/              # 第三层：主题卡片（原子化概念）
├── 03_PARA/               # 第四层：个人创造
│   ├── 00_Projects/       # 当前项目
│   ├── 01_Areas/          # 长期领域
│   ├── 02_Resources/      # 资源（链接到Cards）
│   └── 03_Archives/       # 归档
├── 04_Templates/          # 模板
└── .knowledge/            # 系统文件（向量索引等）
```

### 1.2 书籍命名规则

- **原书**：`书名.md`
- **摘要**：`书名_摘要.md`
- **概念卡片**：`概念名.md`（如`锚定效应.md`）
- **MOC**：`MOC_主题名.md`

## 二、Obsidian AI插件方案

### 2.1 插件对比

| 插件 | 核心功能 | 索引存储 | 特点 |
|------|----------|----------|------|
| **Vault AI Chat** | 内置RAG对话 | 内存（重启重建） | 最简单，5分钟上手 |
| **Copilot** | 无索引语义搜索 | 内存/本地 | 适合大型仓库 |
| **MCP Server** | MCP协议服务器 | 本地Orama | 可被Claude Code调用 |
| **Local GPT** | 100%离线 | 本地 | 隐私优先，需Ollama |
| **Neural Composer** | 知识图谱RAG | LightRAG管理 | 理解关系，需Python环境 |

### 2.2 推荐路径

1. **快速体验**：先装Vault AI Chat
2. **发挥Claude Code能力**：配置MCP Server
3. **需要关系挖掘**：尝试Neural Composer

### 2.3 MCP Server要点

- 将Obsidian变成MCP服务器
- 支持8个工具：搜索、统计、读写文件等
- Claude Code可通过`http://localhost:8080/sse`连接
- 需配置Ollama本地嵌入模型

## 三、书籍转Markdown工具

### 3.1 工具选择

| 书籍格式 | 推荐工具 | 说明 |
|---------|---------|------|
| **EPUB** | booktools | 最简单，一行命令 |
| **PDF** | marker-pdf | 支持扫描件，精度高 |
| **混合格式** | allmark | 17级智能清洗，支持40+格式 |
| **Office文档** | MarkItDown | 微软官方，支持PDF/PPT/Word等 |

### 3.2 allmark核心能力

- 智能去除页眉页脚、页码、元数据
- 修复OCR常见问题（连字符、连字）
- 统一章节格式为`# 第N章`
- 可输出JSONL格式用于AI训练

## 四、RAG技术方案

### 4.1 向量数据库选型

| 数据库 | 特点 | 适用场景 |
|--------|------|----------|
| **Chroma** | 轻量、嵌入式、Python原生 | 个人知识库首选 |
| **FAISS** | 高性能、Meta开源 | 大规模数据 |
| **Qdrant** | Docker部署 | 生产环境 |
| **Orama** | 纯JavaScript | Obsidian插件内置 |

### 4.2 Embedding模型选型

| 模型 | 特点 | 部署方式 |
|------|------|----------|
| **nomic-embed-text** | 轻量、免费、中英支持 | Ollama本地（推荐起步） |
| **bge-large-zh-v1.5** | 中文语义SOTA | 本地/API |
| **BGE-M3** | 多语言、多粒度 | 本地/API |

### 4.3 分块策略

| 内容类型 | 推荐策略 | 块大小 | 重叠率 |
|----------|----------|--------|--------|
| 技术文章 | 基于标题分块 | 按章节 | 无 |
| AI对话 | 语义分块 | 300-500词 | 10% |
| 视频字幕 | 固定大小 | 500词 | 15% |
| 混合内容 | 递归分块 | 先粗后细 | 视情况 |

**经验值**：从500词、15%重叠开始调整

### 4.4 检索优化

**混合搜索**：向量检索（70%）+ 关键词BM25（30%）

**重排序**：召回100个候选，用Cross-Encoder二次打分，精度提升15-20%

### 4.5 评估指标（Ragas框架）

| 指标 | 含义 | 目标值 |
|------|------|--------|
| 忠实度 | 答案是否基于检索文档 | >0.85 |
| 答案相关性 | 答案是否针对问题 | >0.8 |
| 上下文精确率 | 检索文档有多少相关 | >0.7 |
| 上下文召回率 | 相关信息被检索到的比例 | >0.8 |

## 五、Git版本控制

### 5.1 obsidian-git插件配置要点

- 自动保存后提交：开启
- 提交间隔：10分钟
- 自动拉取：开启
- 拉取间隔：30分钟

### 5.2 大型知识库优化

- 启用浅克隆减少仓库体积
- 使用Git LFS管理二进制文件（png/jpg/pdf）
- 配置.gitignore排除缓存和临时文件

### 5.3 多设备同步

- **iOS**：Working Copy + 1Writer
- **Android**：MGit
- **第二台电脑**：直接克隆仓库

## 六、自动化流程

### 6.1 完整流水线

```
采集层 → 处理层 → 存储层 → 索引层 → 检索层
```

1. **采集**：OpenClaw抓取 → Content Core提取 → 存为MD
2. **处理**：AI提取7维度摘要 → 生成概念列表
3. **存储**：按四层结构组织 → Git自动备份
4. **索引**：监控文件变化 → 自动分块向量化
5. **检索**：语义搜索 → AI生成答案+溯源

### 6.2 定时任务建议

- **每天**：AI自动处理新内容，增量更新索引
- **每周**：聚合相关卡片，推荐主题簇
- **每月**：全量重建索引，评估检索效果

## 十、关键提醒

1. **AI能做**：提取原子想法、推荐连接、聚合相关卡片、生成初稿

3. **核心原则**：AI是认知副驾驶，不是自动驾驶
