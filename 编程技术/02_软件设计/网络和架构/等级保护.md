# 网络安全与架构设计总结（等保视角）

## 一、等保 2.0/3.0 概述

### 1. 标准现状
- **等保 3.0**：截至 2026 年 3 月，尚未正式发布。
- **现行标准**：**等保 2.0**（GB/T 22239-2019）。
    - 发布时间：2019 年 5 月 10 日。
    - 实施时间：2019 年 12 月 1 日。

### 2. 等保 2.0 核心变化（常被误称为“3.0”）
- **定级对象扩展**：从传统信息系统扩展至云计算、大数据、物联网、工控、移动互联、区块链。
- **安全框架升级**：从被动防御转为主动防御，提出“一个中心，三重防护”（安全管理中心 + 安全计算环境、安全区域边界、安全通信网络）。
- **技术与管理**：更细化实战化要求（云安全、数据安全、供应链安全等），明确网络运营者主体责任。

## 二、安全域划分与隔离逻辑

### 1. 核心安全域定义
- **互联网**：所有人均可访问，完全不可信区域。
- **DMZ（隔离区）**：对外提供服务的区域（如官网、APP入口、API网关）。作用是挡住外部攻击，不存储核心数据。
- **办公网**：内部员工区域（OA、邮件、文档）。属于高风险区（钓鱼、U盘病毒），不能直接访问生产核心。
- **生产网**：
    - **生产核心区**：存储核心业务、资金、敏感数据的绝对禁区。
    - **生产前置区**：生产网的外层缓冲区，专门接收外部流量（DMZ或专线），抗攻击、不存库。

### 2. 区域隔离目的
- **办公网 vs 生产网**：
    - **风险隔离**：阻断内网横向蔓延（办公网是高风险入口）。
    - **业务连续性**：办公网的故障不影响生产网的高可用性（99.99%+）。
    - **数据防泄露**：生产数据不出域，办公数据不入域。
    - **合规要求**：满足等保三级及金融监管（JR/T 0071）的强制隔离要求。

### 3. 区域间访问规则（拓扑逻辑）
- **互联网 → DMZ**：有限放行（开放 80/443 等）。
- **DMZ → 生产前置区**：逻辑隔离，受控双向通信。允许转发请求，但禁止直连数据库、SSH。
- **生产前置区 → 生产核心区**：生产网内部信任调用，区域隔离。
- **DMZ → 办公网**：**禁止**。DMZ 被攻陷不能直接威胁办公网。
- **办公网 → 生产网**：高风险跨域，需强隔离（网闸/数据摆渡/受控接口）。
- **DMZ × 办公网**：原则上**不互通**。

## 三、架构设计原则

### 1. 纵深防御四层架构
1.  **互联网层**：流量入口。
2.  **DMZ 层（接入层）**：
    - 部署：负载均衡 LB、WAF、API 网关、前端服务。
    - 职责：只做接入、转发、验签，**不存敏感数据，不跑业务逻辑**。
3.  **生产前置区（外网缓冲层）**：
    - 部署：业务网关、认证服务、接口聚合、脱敏/加解密、风控。
    - 职责：接收 DMZ 流量，做安全校验，转发给核心。
4.  **生产核心区（业务与数据层）**：
    - 部署：核心业务服务、数据库、加密机。
    - 职责：只对内提供服务，处理真正的业务与数据。

### 2. 应用拆分与部署策略
- **前后端分离系统**：
    - 前端、静态资源、接口转发放在 DMZ/生产前置。
    - 核心业务逻辑放在生产核心。
    - **优势**：降低核心区流量压力，挡住攻击和渲染压力。
- **单体/前后端不分离系统**：
    - **全部部署在生产核心区**。
    - 若需对外访问，在 DMZ 仅放置 Nginx 反向代理（只转发，不执行业务）。

### 3. 微服务与 K8s 部署
- **按域分组**：一套集群对应一个安全域。
- **注册中心隔离**：
    - DMZ、生产前置、生产核心使用各自独立的注册中心（如 Nacos）。
    - **禁止跨域服务发现**，防止黑客通过注册中心渗透内网。
- **通信方式**：跨域只走 HTTP/HTTPS 接口调用，不走 Feign 或服务发现。

## 四、数据分类与系统组织

### 1. 核心业务定义
满足以下任意一条即为核心业务（必须进生产网）：
- 涉及资金、交易、清算、支付、账户余额。
- 影响客户资产安全。
- 系统停运导致监管通报或重大损失。
- 处理核心敏感数据（身份证、密钥、生物特征）。

### 2. 数据存储原则
- **生产网**：存储真实敏感信息、资金数据、核心配置（不可错、不可丢）。
- **办公网**：存储脱敏数据、审批流程、报表（不碰钱、不碰真数据）。
- **DMZ**：临时缓存入口请求，**绝对不落地存储敏感信息**。

### 3. 跨域业务处理流程（以贷款申请为例）
1.  **DMZ**：接收用户填写信息，加密转发至生产网。
2.  **生产核心**：验真、存储客户信息、风控、生成申请单。
3.  **办公网**：接收生产网推送的**脱敏申请单**，员工审批。
4.  **生产核心**：接收办公网审批指令，执行放款。
- **原则**：跨域只传指令和结果，不传原始敏感数据。

## 五、外部连接与前置机

### 1. 外部接入原则
- **所有外部接口**（互联网 API、专线、第三方对接）必须接入**生产前置区**，禁止直接连生产核心。
- **专线接入**：即使通过专线，也属于不可信流量，需统一收口至生产前置区。

### 2. 银行四大分区
- **生产区**：管钱、管账、管核心。
- **测试区**：测功能。
- **办公区**：管员工、管内部。
- **外联区**：管外部机构、第三方、专线对接（如银联、监管、人行）。

### 3. 前置机（Front-end Machine）的本质
- **定义**：专门为外部第三方系统量身定制的隔离层 + 协议转换层 + 安全适配层。
- **核心作用**：
    1.  **翻译官**：协议转换（如 ISO8583 转 HTTP）、报文拼接。
    2.  **守门员**：安全隔离（外部不进核心）、加解密、验签。
    3.  **缓冲区**：容错、重试、断连补偿。
- **与 API 网关的区别**：API 网关通用；前置机针对特定机构定制（如“银联前置机”、“人行前置机”）。

### 4. 前置机安全性分析
- **不对称权限设计**：
    - 前置机对外权限大（主动发起连接、重试）。
    - 核心对前置机权限极小（只被动应答，不主动回连）。
- **防御逻辑**：
    - 即使前置机被攻破，因核心不主动回连、权限极小、有网闸隔离，黑客无法穿透到核心。
- **前置连前置**：
    - 外联区（别人的前置区）通过专线连接我方生产前置区。彼此核心不暴露。

### 5. 共享服务平台（统一前置）
- 架构：各行各业 → 共享服务平台（鉴权、协议转换） → 业务系统（核心）。
- 本质：即**统一前置区**，比每家一个前置机更集约化。

### 6. 网络隔离与前置部署
- **星型 vs 统一**：
    - **同网同信任**（如政务外网内各单位）：可用统一前置。
    - **异网异信任**（如互联网、政务网、银行专线）：必须分开部署多套前置，避免网络混用和污染。

## 六、网络互通技术细节

### 1. 不同网段互通原理
- **现状**：不同内网网段（如银行 172.x.x.x vs 政务 10.x.x.x）默认无法直接互访。
- **解决方法**：
    - **物理层**：拉通专线。
    - **网络层**：配置双向静态路由（指定下一跳）。
    - **安全层**：防火墙放行策略。
- **实际链路**：政务 → 专线 → 银行防火墙 → 银行外联区/前置机 → 银行核心。核心不允许直接被访问。

### 2. IP 地址冲突解决
- **场景**：接入多个使用相同 IP 段（如都是 172.16.0.0/12）的外部网络，导致路由冲突。
- **解决方案**：NAT（网络地址转换）。
    - **原理**：防火墙将内网源 IP 转换为专线上的专用不冲突 IP。
    - **优势**：对用户透明，支持同时接入多个同网段外部网络。

### 3. 网闸（物理隔离）
- **本质**：通过摆渡数据实现物理隔离，切断 TCP 连接，防止攻击穿透。
- **效果**：对外表现为正常 API 请求，但内部有摆渡延迟，安全性极高。
