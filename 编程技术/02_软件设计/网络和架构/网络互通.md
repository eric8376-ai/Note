# 网络互通与架构设计

## 一、基础网络互通原理

### 1. 核心概念
不同网段的网络之间**不能直接相互访问**。通过**专线**配合正确的**路由配置**，它们可以安全、稳定地通信。
- **专线**：连接两端的高速物理通道。
- **路由配置**：为两边的网络设备指明方向。
### 2. 通信原理（快递类比）
- **二层交换（同网段）**：如同同一个小区，直接送给邻居，无需经过快递站。
- **三层路由（跨网段）**：如同不同小区，必须送到自己小区的**快递站（网关）**，由快递站转发到目的地。连接专线的两端设备（路由器或防火墙）扮演“快递站”角色。
### 3. 配置指南：实现互通
在两端设备上进行“双向指引”并放通安全策略：

**银行端配置**
- **操作**：添加静态路由。
- **内容**：目的网络填写政务网网段（如 `10.0.0.0/8`），下一跳填写专线对端互联IP。
- **作用**：告诉银行设备：“凡是去往 `10.x.x.x` 的数据，都从专线出去。”

**政务端配置**
- **操作**：添加静态路由。
- **内容**：目的网络填写银行网段（如 `172.0.0.0/8`），下一跳填写专线对端互联IP。
- **作用**：告诉政务设备：“凡是去往 `172.x.x.x` 的数据，都从专线走。”

**放通防火墙策略**
- **操作**：检查两端的防火墙或安全策略。
- **作用**：路由解决“怎么走”，防火墙决定“能不能走”。需明确允许两个网段互访。
### 4. 场景示例：Ping 包的传输流程

**环境假设**
- 政务内网电脑：`10.0.0.3`
- 银行内网电脑：`172.0.0.3`
- 政务防火墙：内网口 `10.0.0.2`，专线口 `172.0.0.2`
- 银行防火墙：专线口 `10.0.0.1`，内网口 `172.0.0.1`
**传输步骤**
1. **出发**：电脑 `10.0.0.3` 发现目标不在本网段，将包发给默认网关 `10.0.0.2`（政务防火墙）。
2. **转发（政务端）**：政务防火墙查路由表，发现去往 `172.0.0.0/8` 应走专线口 `172.0.0.2`，下一跳是 `10.0.0.1`。
3. **转发（银行端）**：银行防火墙收到包，发现 `172.0.0.3` 是直连内网，通过内网口 `172.0.0.1` 送达目标电脑。
4. **返回**：目标电脑回包，沿着原路返回给发送者。

## 二、进阶问题：相同网段的冲突与解决方案
### 1. 问题背景
当一个网络试图同时连接两个使用**相同IP段**（如都是 `172.16.0.0/12`）的外部网络时，会发生**路由冲突**。设备无法区分目的地该走哪条路，导致通信失败或混乱。

### 2. 解决方案一：NAT（网络地址转换）—— 银行侧常用
这是最常见、最基础的手段。核心是“变装”。

- **原理**：
  - 内网电脑访问外部网络时，防火墙将**源IP**转换为专线上的一个专用、不冲突的IP。
  - 回包时，防火墙再将目标IP还原给内网电脑。
- **举例**：内网 `10.0.0.5` 访问银行A的 `172.16.1.10`。防火墙将源IP转为 `192.168.1.2` 发送出去。
- **操作细节**：在银行出口防火墙上，将内部地址（如 `10.1.1.2`）转换成专线上唯一的、不会与人行或其他银行冲突的IP地址（例如 `100.64.A.B`）。
- **优势**：
  - 对用户透明，巧妙避免了地址冲突。
  - 允许一个网络同时访问多个同网段的外部网络。
  - 人行端的路由表非常干净，只看到来自专线接口的不同IP。
- **局限**：所有访问通常只能由银行侧主动发起；人行需主动访问时配置较复杂（需静态NAT映射）。
### 3. 解决方案二：MPLS VPN —— 运营商骨干网技术
大型组网（金融网、政务网）中较优雅的解决方案。通过运营商（电信、联通）搭建的**MPLS VPN骨干网**接入。
- **原理**：
  1. **区分（RD）**：运营商分配特定的**路由识别符（RD）**。即使多家用 `10.0.0.0/8`，通过在路由信息前加不同的RD（如 `RD:100:1`），逻辑上区分开。
  2. **隔离（VRF）**：利用**虚拟路由转发（VRF）**，在接入路由器上为每家银行创建“虚拟路由表”。访问工商银行查表A，建设银行查表B，天然隔离。
- **优势**：极高的扩展性和安全性，路由控制灵活。
- **局限**：技术复杂，需运营商支持，设备成本较高。

### 4. 解决方案三：GRE/IPsec 隧道 + 路由隔离
倾向于自建网络，不使用运营商MPLS VPN时的方案。在物理专线或互联网之上建立逻辑隧道，结合路由表隔离。
- **操作步骤**：
  1. **建立隧道**：人行与每家银行间建立 GRE 隧道或 IPsec VPN。
  2. **分配隧道IP**：每条隧道分配唯一的、不冲突的IP（如 `10.254.1.0/30` 给工行）。银行内部真实路由封装在隧道内传输。
  3. **路由隔离**：在汇聚防火墙上启用**策略路由（PBR）**或**虚拟设备上下文（VDC/VSYS）**。从隧道1来的数据查银行A路由表，从隧道2来的查银行B路由表。

## 三、实际的人行组网架构参考
在实际的金融城市网或金宏网中，架构通常如下：
### 1. 接入层
每家银行通过**两家不同运营商（或两条不同路由专线）**接入人行，实现线路冗余。

### 2. 转换层（银行侧）
银行在边界路由器/防火墙上，将内部地址映射成**人行侧规划的特定地址段**。
- **举例**：人行规划工行用 `10.200.1.0/24`，农行用 `10.200.2.0/24`。银行将内部的 `10.x.y.z` 转换成 `10.200.1.z` 发往人行。
- **效果**：虽然都是10段，但 `10.200.1.0` 和 `10.200.2.0` 在人行侧是不同网段，不冲突。

### 3. 核心层（人行侧）
人行的核心路由器/防火墙上运行**BGP（边界网关协议）**。
- **作用**：接收来自几百家银行的路由条目（此时已转换为不冲突网段）。
- **处理**：即使偶尔有冲突，BGP的路由属性（如RD值）也能保证路由精确选择。

## 四、总结
面对几百家银行的互联需求，单纯依靠静态路由是不可能的。现代金融网络架构通过组合技术解决问题：

1. **基础保障**：靠 **NAT** 让银行以“合法身份”进入人行网络。
2. **骨干架构**：靠 **MPLS VPN** 或 **动态路由协议（BGP）** 在承载网上隔离和传播路由。
3. **最终效果**：在人行的核心路由器上，看到一个逻辑清晰、没有冲突的路由表：
   - “去工商银行网段A，走标签100，下一跳是运营商PE设备。”
   - “去建设银行网段B，走标签200，下一跳是另一个接口。”
