# 都有哪些
### 1. **Hadoop**

- **核心组件**：HDFS（分布式存储）、MapReduce（批处理）、YARN（资源调度）。
    
- **应用场合**：
    
    - **批量数据处理**：如日志分析、ETL（数据抽取、转换、加载）1。
        
    - **数据湖存储**：适用于存储海量结构化与非结构化数据6。
        
- **缺点**：不适合实时计算，处理小文件效率低5。
    

### 2. **Spark**

- **特点**：基于内存计算，速度比Hadoop快100倍，支持批处理与流处理（Spark Streaming）。
    
- **应用场合**：
    
    - **实时数据分析**：如金融监控、社交媒体趋势分析（结合Kafka）2。
        
    - **机器学习**：MLlib库支持大规模数据建模，如推荐系统、风险预测6。
        
- **缺点**：内存消耗大，不适合长期存储1。
    

### 3. **Flink**

- **特点**：真正的流批一体化框架，低延迟、高吞吐。
    
- **应用场合**：
    
    - **实时事件处理**：如IoT设备监控、金融交易风控6。
        
    - **流式ETL**：实时数据清洗与转换6。
        

### 4. **Storm / Samza**

- **Storm**：Twitter开发的实时流处理框架，适用于高吞吐低延迟场景（如实时日志处理）1。
    
- **Samza**：LinkedIn开发，与Kafka深度集成，适合实时消息处理（如用户行为跟踪）1。
    

### 5. **Presto / Hive**

- **Presto**：分布式SQL查询引擎，适合交互式分析（如数据仓库查询）5。
    
- **Hive**：基于Hadoop的SQL工具，适用于离线数据分析6。
    

### 6. **ELK Stack（Elasticsearch, Logstash, Kibana）**

- **应用场合**：日志聚合与分析（如服务器监控、安全审计）2。
    

### 主要应用场景总结：

- **实时处理**：Spark Streaming、Flink、Storm16。
    
- **批处理**：Hadoop、Spark15。
    
- **数据存储与管理**：HDFS、HBase、Cassandra6。
    
- **交互式查询**：Presto、Hive5。
    
- **日志与监控**：ELK Stack2。

### 1.2 知识点
####  1.2.1 HDFS（Hadoop Distributed File System）

**物理磁盘的区别**
是分布式文件系统，属于软件层面的数据管理架构，而非磁盘的物理格式（如 NTFS、EXT4、XFS 等）
-HDFS 是运行在操作系统之上的**应用层文件系统**，依赖底层磁盘格式，但自身不格式化磁盘。
在物理磁盘之上构建分布式存储，将文件分块（Block）存储在多台机器的磁盘上。HDFS 的数据块（默认 128MB）最终以普通文件形式存储在底层磁盘上（如 /data/dn/current/ 目录下）。- 底层磁盘的读写性能直接影响 HDFS 的吞吐量（建议使用高性能磁盘如 SSD）。- 
配置 `dfs.datanode.data.dir` 为多个磁盘路径（如 `/disk1/hdfs/data`, `/disk2/hdfs/data`），提升 I/O 并行度。
